```python
class ValidationReport(BaseModel):
    metadata: ValidationMetadata
    shots: list[ShotResult]
    operator_decision: OperatorDecision

class OperatorDecision(BaseModel):
    verdict: str | None = None    # "ready" | "deferred-to-v16+" | "partial" | None
    rationale: str | None = None
    lock_ready: bool = False

class ShotResult(BaseModel):
    shot_id: str
    gen_status: str              # "success" | "failed" | "timeout"
    video_path: str | None
    latency_ms: int | None
    frames: list[FrameIdentityResult]
    error: str | None

class FrameIdentityResult(BaseModel):
    frame_position: str          # "first" | "middle" | "last"
    image_path: str | None
    passed: bool | None
    confidence: float | None
    description: str | None
    error: str | None
```

    Define constants:
    - `VERDICT_DOC_PATH`: resolved relative to the kais-hermes-skills repo root. Compute as `Path(__file__).resolve().parent.parent / "references" / "ltx-flf-iclora-validation.md"` (scripts/ -> kais-movie-pipeline/ -> references/ltx-flf-iclora-validation.md). Also accept `--verdict-doc` flag override.
    - `VALID_VERDICTS`: a frozenset of valid verdict values: `frozenset({"ready", "deferred-to-v16+", "partial"})`.
    - `VERDICT_DESCRIPTIONS`: a dict mapping verdict values to human-readable descriptions for the markdown output:
      - `"ready"`: "Ready for v16+ production rollout (TRANS-11). Identity continuity preserved across FLF frames for character-bearing transitions. Combined workflow stable."
      - `"deferred-to-v16+"`: "Deferred to v17+ or later. Identity drift observed for character-bearing transitions. LTX-2.3 FLF may remain viable for landscape-only match-cuts where identity continuity is not applicable."
      - `"partial"`: "Partial readiness. Identity continuity holds for landscape-only match-cuts but not character match-cuts. Fallback routing per ltx-flf-iclora-validation.md §Background."

    Implement the following functions:

    - `load_validation_report(path: Path) -> dict`: Read JSON from `path` with `encoding="utf-8"`. Return the parsed dict. Raise `FileNotFoundError` if the file does not exist. Raise `ValueError` with a specific message if the JSON is malformed or missing the `operator_decision` key. (Mirrors Phase 77 `load_benchmark_report`.)

    - `validate_verdict(report: dict) -> tuple[str, str, list[str]]`: Run the 4-check validation. Returns a tuple of `(verdict, rationale, errors)`. If `errors` is non-empty, the verdict update should be refused.
      - Check 0 (lock_ready guard): Read `report["operator_decision"]["lock_ready"]`. If `False`, append error `"operator_decision.lock_ready is false — operator must set lock_ready: true in the report before updating verdict"`.
      - Check 1 (non-null verdict): Read `report["operator_decision"]["verdict"]`. If `None` or empty string, append error `"operator_decision.verdict is null — operator must fill the verdict in the report"`. Also verify the value is a string type (not array/dict) to guard against malformed JSON.
      - Check 2 (valid verdict value): If verdict is non-null, check if it's in `VALID_VERDICTS`. If not, append error `f"verdict '{verdict}' is not valid — must be one of: {', '.join(sorted(VALID_VERDICTS))}"`.
      - Check 3 (non-null rationale): Read `report["operator_decision"]["rationale"]`. If `None` or empty string (after strip), append error `"operator_decision.rationale is null — operator must provide a rationale citing validation results"`.
      - Return `(verdict, rationale, errors)`.

    - `check_overwrite_guard(verdict_doc_path: Path, force: bool) -> str | None`: Read the verdict doc markdown. Search for a line matching `**Verdict (locked**: ` or `[x] **` pattern in the Production-Readiness Verdict section that indicates a verdict has already been recorded. If a locked verdict is found and `force` is `False`, return an error string `f"Verdict already locked in {verdict_doc_path} — use --force to overwrite"`. Otherwise return `None`. (Mirrors Phase 77 `check_overwrite_guard`.)

    - `format_verdict_block(verdict: str, rationale: str, report: dict) -> str`: Build the markdown text for the verdict block. The block must include:
      - The verdict value with its description from `VERDICT_DESCRIPTIONS`
      - The operator's rationale
      - A timestamp (ISO 8601 UTC date)
      - A summary of validation results extracted from `report["shots"]` (per-shot gen_status + identity-continuity confidence for first/middle/last frames)
      - A "locked" marker: `<!-- verdict-locked: {verdict} @ {timestamp} -->` as an HTML comment for programmatic detection by `check_overwrite_guard`

    - `write_verdict(verdict_doc_path: Path, verdict: str, rationale: str, report: dict) -> None`: Read the current verdict doc markdown with `encoding="utf-8"`. Find the `## Production-Readiness Verdict` section. Replace the content between the `## Production-Readiness Verdict` heading and the next `##` heading (or `---` separator) with the formatted verdict block from `format_verdict_block()`. Write the full markdown back using atomic write (tempfile + os.replace, mirroring Phase 77 `write_lock` pattern). Do NOT modify any other section of the document.

    - `main()`: Parse argparse args: `--validation-report` (required, path to JSON report from runner), `--verdict-doc` (optional, default to `VERDICT_DOC_PATH` constant), `--force` (flag, default False). Load report. Run `check_overwrite_guard` — if error, print to stderr and `sys.exit(1)`. Run `validate_verdict` — if errors non-empty, print each error to stderr and `sys.exit(1)`. Run `write_verdict`. Print success message: `f"Verdict '{verdict}' written to {verdict_doc_path}"`. Print the verdict block that was written. Print next-step reminder: `"Commit the verdict doc with message: chore(78-02): record TRANS-07 verdict={verdict} after LTX-FLF validation"`.

    Error handling: All `open()` calls use `encoding="utf-8"`. Catch `json.JSONDecodeError` and `KeyError` in load functions and re-raise as `ValueError` with context about which file and which key.

    The script must NOT auto-recommend a verdict based on vision_verify confidence scores. Identity drift is qualitative (confidence != drift severity). Operator judgment is required per D-03.
