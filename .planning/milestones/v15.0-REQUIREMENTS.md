## v15.0 Requirements

Requirements for v15.0 milestone. Each maps to roadmap phases (Phase 77+, continuing from v14.0 Phase 76)。

### DUB-05 — CosyVoice A/B Benchmark Runner

- [x] **DUB-05-RUNNER**: User can run `python scripts/run_cosyvoice_benchmark.py --dialogue-lines <file> --variants cosyvoice_2_0_0_5b,fun_cosyvoice_3_0` to execute side-by-side A/B benchmark across CosyVoice 2.0-0.5B + Fun-CosyVoice 3.0 on operator-provided dialogue lines; script outputs structured JSON report + audio files for human review
- [x] **DUB-05-LOCK**: User can run `python scripts/lock_cosyvoice_default.py --benchmark-report <path>` to lock the chosen variant in `VERSION.json.tts.cosyvoice_default_variant` with rationale captured from the benchmark report (operator decision; NOT auto-pick-lower-WER)

### TRANS-07 — LTX-FLF+ICLoRA Validation Runner

- [x] **TRANS-07-WORKFLOW**: User can read `references/workflows/ltx-flf-iclora-validation.json` ComfyUI workflow (LiconMSR + LTXVConditioning + SamplerCustomAdvanced node graph per community reports) for 1-2 reference shot validation
- [x] **TRANS-07-RUNNER**: User can run `python scripts/run_ltx_flf_validation.py --reference-shots <dir>` to submit 1-2 reference shots through the validation workflow + capture results (gen_status, latency, identity-continuity assessment via vision_verify) + write verdict to `references/ltx-flf-iclora-validation.md`
- [x] **TRANS-07-VERDICT**: User can read production-readiness verdict (ready / deferred-to-v16+) in `ltx-flf-iclora-validation.md` after operator runs validation; gates TRANS-11 v16+ production rollout

### IMG-09 — Vision-Verify False-Positive Calibration

- [x] **IMG-09-CALIBRATE**: User can run `python scripts/calibrate_vision_verify.py --metrics-buffer <path>` to analyze production MetricsBuffer data + recommend confidence threshold per stratum (1-ref/3-ref/5-ref) using false-positive rate analysis
- [x] **IMG-09-APPLY**: User can apply calibrated thresholds via `vision_verify.py` config (per-stratum threshold override) with audit log of when/why thresholds changed

### DUB-03 — Voice Sample Collection Protocol

- [x] **DUB-03-PROTOCOL**: User can read `references/voice-sample-collection-protocol.md` for per-character voice sample collection protocol (3-10s clean recording guidelines, environment requirements, file naming convention `assets/<episode>/voice_refs/<character>.wav`)
- [x] **DUB-03-BATCH-VALIDATE**: User can run `python scripts/validate_voice_clone_batch.py --voice-refs-dir <dir>` to batch-validate all voice_clone_reference_wav files in an episode against 3-10s + wav + ≥16kHz + mono rules; outputs pass/fail report per character

### XCUT-04b — Cloud Engine Bootstrap

- [x] **XCUT-04b-DOCS**: User can read `references/cloud-engine-bootstrap.md` for Hailuo 02 i2v Pro + Vidu keyframe-to-video API key acquisition steps + ComfyUI Wan2.2 FLF2V custom node install procedure + cost-estimation worksheet (per-shot + monthly projections)
- [x] **XCUT-04b-OPTIN**: User can opt in per cloud engine via `~/.hermes/config.yaml` cloud_engines block (hailuo_api_key + vidu_api_key + wan22_comfyui_node_enabled); transition-engine-routing.md rules consume opt-in state at runtime

### XCUT-04c — GLM-4.6V Cost Tracking

- [x] **XCUT-04c-INSTRUMENT**: `dreamina_stats.py` MetricsBuffer extends to track per-batch GLM-4.6V token spend (input_tokens + output_tokens + estimated_cost_usd) alongside existing per-task latency/success rate
- [x] **XCUT-04c-CLI**: User can run `hermes glm stats` CLI subcommand to see monthly GLM-4.6V aggregate spend (token count + estimated USD cost) + per-stratum breakdown; reuses Rich table formatting from `hermes dreamina stats`

### Cross-cutting — v14.0 tech_debt closure + lineage

- [x] **XCUT-05-AUTO**: User can run `python scripts/bump_all_agent_lineage.py` to automate full 15-agent lineage bump (v14.0 XCUT-05 deferred; the script wraps `transform_skill_to_agent.py` for all 15 active experts + handles Track B 6 v13.0 P62 manual cases)
- [x] **VALIDATE-V15**: v15.0 VALIDATE phase re-runs `76-meta-rule-x2-audit.sh` + extends coverage to any new v15.0 `_INSTRUCTION` constants; closes v14.0 tech_debt items where operator-action data has flowed back to code (DUB-05 lock / IMG-09 thresholds applied / TRANS-07 verdict recorded)
